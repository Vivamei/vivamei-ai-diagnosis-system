# 05 · 微信小程序接入

## 适用读者与目标

本文档面向要把本项目的小程序端接入微信、并发布到线上的技术人员。前置条件是 H5 侧已按 [02-部署实施.md](./02-部署实施.md) 部署完成、[03-部署验证.md](./03-部署验证.md) 通过。

**先明确一点:小程序代码不需要「嵌入」或「移植」。** `apps/miniapp` 已经是一个完整可构建的 Taro 小程序,首页、登录、拍照、分析、报告、预约、法务页共 9 个页面全部就绪(见 `apps/miniapp/src/app.config.ts`)。本文档要做的是把这份代码与**一个真实的小程序账号**和**一个已备案的 HTTPS 域名**接上,再走完微信的审核发布流程。

本阶段目标:

- 注册小程序账号,取得 AppID 与 AppSecret。
- 在微信公众平台配置服务器域名白名单。
- 后端从 mock 微信切换到真实微信开放接口。
- 构建小程序产物,导入开发者工具,上传体验版并提交审核。

预计操作耗时 3 至 4 小时(不含小程序账号认证 1 至 3 个工作日、ICP 备案 1 至 2 周的等待时间)。

本文档只讲**接入与上线**。双端代码差异、API 基址策略、登录双模、目录结构等开发向内容见 [references/MINIAPP.md](./references/MINIAPP.md)。

## 0. 全流程一览

```
① 注册账号 ──────────► AppID + AppSecret
                              │
② 域名备案 + HTTPS ──► 微信后台配 3 个域名白名单
                              │
③ 后端切真微信 ──────► /etc/venus-4s/.env 填 WX_*,ALLOW_MOCK 去掉 wechat
                              │
④ 填前端配置 ────────► config/frontend.env 的 WX_APPID
                              │
⑤ 构建 ──────────────► pnpm --filter @venus/miniapp build:weapp
                              │
⑥ 开发者工具 ────────► 导入 apps/miniapp
                              │
⑦ 三段联调 ──────────► 本机 mock → 本机真微信 → 真机 HTTPS
                              │
⑧ 上传体验版 ────────► 提交审核 → 发布
```

其中 ① 和 ② 是长周期阻塞项,应在项目立项时就与 ICP 备案一起启动。

## 1. 注册小程序账号

在 [mp.weixin.qq.com](https://mp.weixin.qq.com) 注册小程序。

**必须使用企业主体。** 本项目的小程序登录走的是微信手机号快速验证(`apps/miniapp/src/pages/login/index.tsx:207` 的 `<Button openType='getPhoneNumber'>`),该接口不对个人主体开放。个人主体注册完会发现登录链路根本跑不通,且无法补救,只能重新注册,所以这一步不要图省事。

注册完成后:

| 操作 | 位置 | 产出 |
|---|---|---|
| 主体认证 | 设置 → 基本设置 | 认证通过(1 至 3 个工作日) |
| 取 AppID | 开发管理 → 开发设置 | `wx` + 16 位十六进制,如 `wx1234567890abcdef` |
| 取 AppSecret | 开发管理 → 开发设置 | **只显示一次**,当场存进密码管理器 |
| 开通手机号快速验证 | 开发管理 → 接口设置 | 按微信当期规则计费 |
| 填写服务类目 | 设置 → 基本设置 → 服务类目 | 医美相关类目通常需要上传资质,以后台实际提示为准 |

AppSecret 属于后端密钥,与数据库密码同级,禁止写入仓库任何文件。它的唯一落点是服务器上的 `/etc/venus-4s/.env`(见 §3)。

## 2. 域名与白名单

小程序只能访问 **HTTPS、443 端口、已 ICP 备案** 的域名,不能带端口号、不能用 IP。域名备案与证书的办理见 [01-部署前准备.md](./01-部署前准备.md)。

在「开发管理 → 开发设置 → 服务器域名」配置以下三项,全部填生产域名(下表以 `rernaco.com` 为例):

| 白名单类型 | 填写内容 | 对应代码 | 漏配的表现 |
|---|---|---|---|
| request 合法域名 | `https://rernaco.com` | 普通 API 与 `/api/analyze/{id}/stream` 分块 SSE | 所有请求报「url 不在合法域名列表中」 |
| uploadFile 合法域名 | `https://rernaco.com` | `apps/miniapp/src/api/upload.ts` 照片上传 | 拍完照上传失败 |

分析进度与 H5 共用 SSE 地址。H5 用 `EventSource`,微信端用
`Taro.request({ enableChunked: true })` 读取同一条流,因此**不需要 socket 合法域名**。
`request` 与 `uploadFile` 虽然填写同一个 HTTPS 域名,仍要在微信后台分别配置。

**downloadFile 合法域名暂时不用配。** 当前 `config/frontend.env` 的小程序段 `BRAND_LOGO_URL` 留空,logo 用的是包内 `src/assets/brand-logo.png`。只有以后把 logo 换成 OSS 外链时,才需要把 OSS 域名加进 downloadFile 白名单。

Nginx 侧不需要改动:`infra/nginx/edge.conf` 已为 `/api/analyze/*/stream`
关闭代理缓冲并把读取超时延长到 3600 秒。

## 3. 后端切换到真实微信

### 3.1 当前状态:显式 mock

`config/prod.baseline.env:34` 现在是:

```
ALLOW_MOCK=wechat,moderation
```

也就是说生产环境**明知故犯地**在用 mock 微信。此时 `apps/api/app/services/wechat.py` 的 `is_wx_configured()` 恒为 `false`,行为是:

- `code2session` 不调微信,openid 由 `wx.login` 的 code 派生 —— 换台机器登录就变成另一个用户;
- `getPhoneNumber` 不调微信,返回 `SMS_TEST_PHONE_PREFIX` 打头的假号。

这是小程序内测期的有意设计:没拿到 AppID 也能把登录链路跑通。启动时 preflight 会打 WARNING 提示这件事,不会静默。

### 3.2 填密钥

在 ECS 上编辑 `/etc/junction/../etc/venus-4s/.env`(即 `docker-compose.ecs.yml` 里 `env_file` 指向的文件),追加:

```
WX_APPID=wx1234567890abcdef
WX_SECRET=<第 1 节取到的 AppSecret>
```

> **不要写进 `config/prod.baseline.env`。** 该文件会被 `COPY` 进镜像并推送到 ACR,任何能拉到镜像的人都能看到。`infra/build.sh` 对一批敏感键名做了硬性拦截,写进去会直接构建失败。

### 3.3 关掉 mock

同样在服务器上,把 `ALLOW_MOCK` 里的 `wechat` 去掉:

```
ALLOW_MOCK=moderation
```

`ALLOW_MOCK` 是全项目唯一的 mock 开关,没列进名单的子系统一旦缺凭据就拒绝启动。所以这一步做完,如果 `WX_APPID`/`WX_SECRET` 没填对,容器会**启动失败并明确报错**,而不是带着降级悄悄跑起来——这正是期望行为。

重启容器即生效,**不需要重新打镜像**:

```bash
cd /opt/venus-4s
docker compose -f docker-compose.ecs.yml up -d api
docker compose -f docker-compose.ecs.yml logs -f api | head -40
```

启动日志里不再出现 `[preflight] 显式放行 mock:wechat` 即为切换成功。

## 4. 填前端配置

前端配置的唯一真源是 `config/frontend.env`。改它的 `[小程序专用]` 段:

```
WX_APPID=wx1234567890abcdef     # 原来留空
API_BASE=https://rernaco.com     # 已是生产域名,一般不用动
```

`WX_APPID` 是公开信息(小程序包可被解包),放在这里没有安全问题;AppSecret 是密钥,只能在后端(§3.2)。

> **不要手改 `apps/miniapp/.env.development` 和 `.env.production`。** 这两个文件是 `scripts/gen-frontend-env.mjs` 的生成产物,每次构建都会被覆盖,手改的内容会静默丢失。

## 5. 构建

```bash
pnpm install                                # 仓库根目录,一次覆盖 3 个 workspace
pnpm --filter @venus/miniapp build:weapp
```

`build:weapp` 串了三步(见 `apps/miniapp/package.json`):

1. `gen-env` —— 从 `config/frontend.env` 生成 `apps/miniapp/.env.production`;
2. `sync-appid.mjs production` —— 把 `TARO_APP_WX_APPID` 写进 `project.config.json`;
3. `taro build --type weapp` —— 产出 `apps/miniapp/dist/weapp`。

第 2 步存在的原因:`project.config.json` 是微信开发者工具直接读的静态文件,不参与 Taro 构建,Taro 注入的环境变量到不了它里面。而 AppID 又必须和域名配置一起变(换主体 = 换 AppID + 换备案域名),分散在两处很容易只改一半,表现为「上传到了错误的小程序」或「域名白名单对不上」,这两种错都要到真机上才暴露。

脚本会校验格式,只放行 `wx` + 16 位十六进制或开发者工具的游客号 `touristappid`。AppID 留空时它不报错也不改文件,保持原样——本地用游客号跑流程是常规用法。

构建后可自查产物里确实带上了绝对基址:

```bash
grep -r "rernaco.com" apps/miniapp/dist/weapp --include=*.js -l | head -3
```

## 6. 导入微信开发者工具

「导入项目」时,**目录选 `apps/miniapp`**,不是 `apps/miniapp/dist/weapp`。`project.config.json` 在 `apps/miniapp` 这一层,其中 `miniprogramRoot: "dist/weapp/"` 已指向产物目录。AppID 会自动读到 §5 刚同步好的值。

`project.config.json` 的 `setting.urlCheck` 已设为 `false`,这样本地联调时能直连 `http://localhost:8080`。这个开关只影响开发者工具的模拟器,不影响真机和线上——真机永远强制校验域名白名单。

## 7. 三段联调

不要一步跳到线上,按下面三段推进,每段只引入一个变量。

### 7.1 本机 + mock 微信

```bash
pnpm --filter @venus/miniapp dev:weapp
```

watch 模式,读 `.env.development`(`API_BASE=http://localhost:8080`)。后端本机起 `start-dev.bat` 即可,`config/dev.env` 保持默认的全 mock。

这一段验证界面与流程:首页 → 登录 → 拍照 → 分析等待 → 报告 → 分型详情 → 预约。微信侧仍是假 openid、假手机号,不影响页面逻辑。

### 7.2 本机 + 真实微信

`config/dev.env` 填上 `WX_APPID`/`WX_SECRET`,并从 `ALLOW_MOCK` 去掉 `wechat`,重启后端。重点验证登录链路:

```
wx.login 拿 code
  → POST /api/auth/wx/login       返回 needPhone=true + bindToken
  → 用户点「手机号快速验证」按钮,拿到 phoneCode
  → POST /api/auth/wx/phone       用 bindToken 里的 openid + phoneCode 换真实手机号
  → 返回 accessToken / refreshToken
```

需要覆盖的两个分支(见 `apps/api/app/routers/auth.py`):

- **新用户**:建号,写入 openid、unionid、加密手机号、授权时间与协议版本;
- **老用户**(此前用短信在 H5 注册过):按手机号哈希命中既有账号,把 openid 补绑上去,**不开新号**。这条要专门测,否则同一个人会有两个账号。

openid 一律从服务端签发的 `bindToken` 里取,不信客户端自报,这是防越权绑定的关键,联调时不要为了方便去改它。

### 7.3 真机 + 生产域名

`build:weapp` 出生产包,开发者工具里点「预览」扫码。真机上 `localhost` 不通,必须走 `https://rernaco.com`,同时会真正校验 §2 的域名白名单——socket 漏配的问题就在这一步暴露。

必测项:分析等待页的进度是否持续推进(验 WSS)、拍照上传是否成功(验 uploadFile)、报告页保存图片到相册是否正常(`components/ReportExport.tsx`,用 Canvas 重绘后 `canvasToTempFilePath` + `saveImageToPhotosAlbum`)。

## 8. 上传、审核与发布

1. 开发者工具点「上传」,填版本号与备注,产物进入 mp 后台「版本管理」的开发版。
2. 在后台把开发版设为**体验版**,添加体验成员,用真机把 §7.3 的必测项再走一遍。
3. 提交审核。需要提前准备的材料:
   - 服务类目及对应资质(医美类目通常需要);
   - **用户隐私保护指引**。本项目用到手机号、相册写入(`saveImageToPhotosAlbum`)、选择图片(`chooseMedia`)三类用户信息,必须在后台逐条声明,声明缺项是常见的驳回原因;
   - 审核用测试账号与操作说明(审核员需要能走通完整流程)。
4. 审核通过后在「版本管理」点发布。

## 9. 上线后检查项

| 检查项 | 方法 | 期望 |
|---|---|---|
| 后端确实在用真微信 | `docker compose logs api \| grep preflight` | 无 `显式放行 mock:wechat` |
| openid 稳定 | 同一微信号退出后重新登录 | 落到同一个用户,不新建账号 |
| 手机号真实 | 查库中新用户的手机号前缀 | 不是 `SMS_TEST_PHONE_PREFIX` 开头 |
| WSS 可用 | 真机跑一次分析 | 等待页进度持续推进,不卡住 |
| 老用户合并 | 用一个已在 H5 注册过的手机号走微信登录 | 绑到既有账号,不产生重复用户 |

## 10. 常见问题

**Q:AppSecret 泄露了怎么办?**
在 mp 后台「开发管理 → 开发设置」重置,然后更新服务器 `/etc/venus-4s/.env` 并重启 api 容器。`services/wechat.py` 对微信返回的 `errcode 40001`(access_token 失效)做了处理:自动清 Redis 缓存让下次重取,所以改完 secret 不需要手动清缓存。

**Q:换主体 / 换域名要改哪些地方?**
四处,缺一不可:mp 后台的三个域名白名单、`config/frontend.env` 的 `WX_APPID` 与 `API_BASE`、服务器 `/etc/venus-4s/.env` 的 `WX_APPID`/`WX_SECRET`、`config/prod.baseline.env` 的 `APP_BASE_URL`/`WEB_BASE_URL`。前两处改完要重新 `build:weapp` 并重新上传。

**Q:H5 和小程序是两套代码吗?**
不是。`apps/miniapp` 一套 Taro 代码可以同时出小程序包和 H5 包,`apps/web` 是另一套独立的 Vite H5(当前线上 H5 用的是它)。两端的文案与配置共用 `config/frontend.env` 一份真源。详见 [references/MINIAPP.md](./references/MINIAPP.md) §1、§11。

**Q:小程序审核期间能改后端吗?**
能。审核只针对小程序前端包。但注意不要在此期间改动接口的请求/响应结构,否则审核员看到的行为可能与提交时不一致。
