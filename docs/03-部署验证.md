# 03 · 部署验证

## 适用读者与目标

本文档面向已完成 [02-部署实施.md](./02-部署实施.md) §12 阶段检查的技术人员。

本阶段目标:从公网访问者视角完整验证部署结果,确认服务可正常对外提供。

预计操作耗时 30 至 60 分钟。

## 1. 验证 DNS 解析

在本地机器执行:

**Linux 或 macOS:**

```bash
nslookup <你的域名>
dig <你的域名>
```

**Windows PowerShell:**

```powershell
nslookup <你的域名>
```

预期解析结果的 IP 与 ECS 公网 IP 一致。

若解析结果不符合预期:

- 无法解析:确认 [01 §11.3](./01-部署前准备.md#113-配置-dns-解析) 中的 A 记录已添加。新增记录一般数分钟生效,最长 30 分钟。
- 解析到其他 IP:可能存在历史绑定或 CDN 配置,进入 DNS 控制台确认 `@` 与 `www` 记录均指向当前 ECS 公网 IP。
- 部分网络仍未生效:DNS 缓存所致,可切换网络后重试。

## 2. 验证端口连通性

在本地机器执行:

```bash
nc -zv <你的域名> 443
nc -zv <你的域名> 80
```

若端口不通,按以下顺序排查:

- 检查 ECS 安全组入方向规则,确认 80 与 443 端口对 `0.0.0.0/0` 开放。
- 检查 web 容器状态:在 ECS 上执行 `docker compose -f /srv/venus-4s/infra/docker-compose.ecs.yml ps`,确认 web 容器为 `Up` 状态。
- 检查 ECS 系统防火墙:`iptables -L -n | grep -E '80|443'`。

## 3. 验证 SSL 证书

执行:

```bash
curl -vI https://<你的域名>/health 2>&1 | grep -iE 'subject|issuer|expire|SSL certificate verify'
```

或使用 openssl:

```bash
openssl s_client -connect <你的域名>:443 -servername <你的域名> </dev/null 2>/dev/null \
    | openssl x509 -noout -subject -issuer -dates
```

预期结果:

- `subject` 包含目标域名(或匹配的通配符域名)
- `SSL certificate verify ok`
- 证书在有效期内

常见问题:

| 现象 | 原因 |
|---|---|
| `unable to get local issuer certificate` | 证书链不完整。上传的可能是仅含终端证书的 `cert.pem`,而非包含中间 CA 的 `fullchain.pem`。参考 [01 §11.4](./01-部署前准备.md#114-申请-ssl-证书) 重新下载 Nginx 格式证书 |
| `certificate has expired` | 证书已过期,需要重新申请 |
| `Subject Alternative Name doesn't match` | 证书域名与实际访问域名不一致 |

浏览器打开 `https://<域名>` 时,地址栏应显示锁形图标,单击图标可确认证书详情。

## 4. 验证 HTTP 至 HTTPS 跳转

执行:

```bash
curl -sI http://<你的域名>/ | head -3
```

预期返回:

```
HTTP/1.1 301 Moved Permanently
Location: https://<你的域名>/
```

若未返回 301,可能是 `edge.conf` 未生效。在 ECS 上重启 web 容器:

```bash
docker compose -f /srv/venus-4s/infra/docker-compose.ecs.yml restart web
```

## 5. 验证健康检查接口

执行:

```bash
curl -s https://<你的域名>/health
```

预期返回:

```json
{"status":"ok"}
```

常见异常:

| 响应 | 可能原因 |
|---|---|
| 502 Bad Gateway | nginx 无法连接至 api 容器,查看 `docker compose ... logs web api` |
| 504 Gateway Timeout | api 响应超时,检查数据库或 Redis 连接状态 |
| 返回 HTML 页面 | 请求走了 SPA fallback,检查 `edge.conf` 中 `location = /health` 配置 |

## 6. 验证前端页面加载

在浏览器中打开 `https://<你的域名>/`,预期结果:

- 页面正常渲染,无 404、500 等异常状态。
- 打开浏览器开发者工具的 Network 面板并刷新,确认:
    - `/`(index.html)返回 200
    - 静态资源(.js、.css)均返回 200,响应头包含 `Cache-Control: public, immutable`
    - 无 Mixed Content 警告(HTTPS 页面中不应加载 HTTP 资源)
- Console 面板无红色错误(黄色警告可暂时忽略)

## 7. 端到端业务链路验证

依次验证以下业务场景。

### 7.1 手机号登录

操作:在前端输入手机号,单击"获取验证码",输入收到的验证码完成登录。

预期结果:手机接收到内容符合 [01 §7.3](./01-部署前准备.md#73-申请模板) 中申请模板格式的短信,登录后获取到有效 token。

若未收到短信:

- 查看 api 日志:`docker compose -f /srv/venus-4s/infra/docker-compose.ecs.yml logs api | grep -i sms`
- 进入阿里云短信服务控制台的"发送记录"页面,查看发送状态与错误码
- 常见原因:签名或模板未通过审核、手机号被运营商反垃圾拦截、账户余额不足

### 7.2 照片上传

操作:通过前端上传照片。

预期流程:前端向后端请求 STS 临时凭证,前端使用凭证直传 OSS。

预期结果:阿里云 OSS 控制台的目标 Bucket 中,`uploads/` 前缀下出现新对象。

若上传失败:

- 检查浏览器开发者工具中请求返回码。403 错误的常见原因:
    - `OSS_STS_ROLE_ARN` 配置错误
    - RAM 角色的自定义策略中 Bucket 名称与实际 Bucket 不一致
    - RAM 角色的信任策略未允许应用侧子账号 assume

### 7.3 分析请求(SSE 流式)

操作:在前端触发分析。

预期流程:请求类型为 `eventstream`,响应头包含 `Content-Type: text/event-stream`,前端页面看到分析结果逐段渲染。

若结果一次性完整返回而非流式:

- nginx 未关闭 buffering。检查 `edge.conf` 中 `location ~ ^/api/analyze/.+/stream$` 段,应包含:

```nginx
proxy_buffering off;
proxy_cache off;
proxy_read_timeout 3600s;
```

- 修改后使用 scp 覆盖 ECS 上的对应文件,执行 `docker compose ... restart web`。

若分析中断:

- 验证 LLM 服务可达性:`docker compose ... exec api curl -v <LLM_SYNC_BASE_URL>/`
- 查看日志中是否包含 `LLM_TIMEOUT` 或 `RUNNER_EXCEPTION`

### 7.4 分析结果持久化验证

在 ECS 上直接查询 RDS:

```bash
mysql -h rm-xxxxxx.mysql.rds.aliyuncs.com -u venus -p venus \
    -e "select id, user_id, status, created_at from analyses order by id desc limit 5"
```

预期返回近期分析记录。

## 8. 微信 H5 场景验证

若项目对接微信生态,在微信内打开 `https://<你的域名>/`。

预期结果:

- 页面正常打开,不出现"该网站未通过安全检测"提示。
- 可完成登录、上传、分析全流程。

若出现拦截提示:

- 确认域名已加入公众号后台的"JS 接口安全域名"与"业务域名"白名单。
- 如需临时规避,可通过备用域名、公众号菜单入口或扫码方式访问。

## 9. 冒烟测试复核

再次执行冒烟测试,验证公网访问路径:

```bash
HOST=https://<你的域名> bash scripts/smoke.sh
```

脚本覆盖 5 项检查:

- 健康检查接口返回 `status:ok`
- OpenAPI 文档可访问
- 短信重复请求触发 429 限流
- 错误验证码返回 400
- 首页返回 200

预期最终输出 `smoke OK`。

## 10. 上线验收清单

**网络与证书**

- [ ] `nslookup` 解析结果为 ECS 公网 IP
- [ ] `nc -zv` 确认 80 与 443 端口连通
- [ ] `curl -I https://<域名>/health` 返回 200,证书信息正确且未过期
- [ ] HTTP 请求 301 跳转至 HTTPS

**容器与后端**

- [ ] `docker compose ... ps` 显示三个容器均为 `Up`,api 为 `(healthy)`
- [ ] `docker compose ... logs api` 最近 200 行无反复出现的 ERROR
- [ ] `docker compose ... logs cron` 显示定时任务已运行

**业务链路**

- [ ] 手机号登录:短信发送成功、验证码校验通过、token 获取成功
- [ ] 照片上传:OSS 中出现新对象
- [ ] 分析请求:SSE 流式返回,分析结果写入数据库
- [ ] 微信内访问无拦截(如适用)

**运营准备**

- [ ] 明确 RDS、KVStore、OSS 监控指标查看路径
- [ ] 建议在阿里云控制台为 ECS、RDS、KVStore 配置 CPU、连接数、磁盘等告警
- [ ] 密钥文件(`PHONE_DEK_BASE64`、`PHONE_HMAC_KEY`、AccessKey)已离线备份
- [ ] 团队已知悉:修改密钥类配置只需编辑 `/etc/venus-4s/.env` 后 `docker compose ... restart api cron`,无需重新构建镜像

以上清单全部通过后,部署完成。

后续运维、故障排查、备份恢复、迁移相关内容参见 [04-日常运维与排查.md](./04-日常运维与排查.md)。
