## 7.2 内容安全双层防线

```
用户图片
  │
  ├─上传后异步─► 阿里云内容安全 imageScan  ┐
  │                                       │ 任一不过 → photo.moderation_status='rejected'
  │              本地图片审计(尺寸/类型)   ┘   → /api/analyze 直接 422
  ▼
LLM 流式输出（每条 delta 实时拼接）
  │
  └─全文完成─► 本地敏感词库.match(违禁词正则)
                                     │
                                     └─► 命中 → reports.moderation_status='rejected'
                                              → 前端显示降级文案
                                              → 写 audit_log + 报警
                ► 阿里云内容安全 textScan
                                     │
                                     └─► 命中 → 同上
```

**敏感词库来源**（按优先级）：
1. 卫健委 + 国家市监局公开的医疗违禁词清单
2. 阿里云内容安全的"医疗专项词库"（接 API 即可）
3. 客户自己积累的内部敏感词（admin 用 CLI 加，本期无后台 UI）

## 7.3 隐私协议与同意机制

两份文档落 `apps/web/public/legal/`：
- `privacy-v1.0.md`：信息收集（手机号/人脸/IP/UA）、用途、留存期、第三方共享（阿里云/LLM 厂商）、用户权利（查询/删除/撤回）
- `terms-v1.0.md`：免责声明（非医疗诊断）、4S 报告主观性提示、争议管辖

**同意机制**：
- 用户每次首次进入 `/capture` 或 `/booking`，若 `localStorage.consentVer !== '1.0'`，弹 `<ConsentDialog>`
- 勾选后写 localStorage + 调 `/api/auth/sms/verify` 时把 `consentVer` 上传（落 `users.consent_at / consent_ver`）
- 协议升版后强制重新弹

## 7.4 服务器端日志与留痕

- **结构化日志**：JSON 行，包含 `trace_id / user_id / action / target_id`，Loguru 同时写两路：
  - 本地文件 → logrotate（180 天），保证不依赖外部服务也能查
  - 阿里云 SLS（详见 8.4），用于跨机查询、关键字告警
- **审计日志**：所有"涉敏感数据 / 涉合规判定"动作落 `audit_logs` 表，明文存 6 个月以上
- **请求 trace**：每个 HTTP 请求生成 `X-Request-Id`（ULID），前后端串联便于排障
