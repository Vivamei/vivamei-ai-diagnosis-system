# 04 · 日常运维与排查

## 适用范围

本文档面向项目上线后的日常运维工作,包括发布、回滚、备份、扩容、故障排查、性能观察等内容。

## 1. 发布与回滚

### 1.1 常规发布

**本地构建并推送新镜像**:

```bash
cd venus-4s
bash infra/build.sh --tag=$(date +%Y%m%d-%H%M) --push
```

记录终端输出的 `API_IMAGE` 与 `WEB_IMAGE` 变量。

**在 ECS 上更新镜像并重启**:

```bash
cd /srv/venus-4s/infra
export API_IMAGE=registry.cn-hangzhou.aliyuncs.com/venus/api:<新TAG>
export WEB_IMAGE=registry.cn-hangzhou.aliyuncs.com/venus/web:<新TAG>

# 存在新的数据库迁移时执行,无新迁移可跳过
docker compose -f docker-compose.ecs.yml run --rm api alembic upgrade head

docker compose -f docker-compose.ecs.yml pull
docker compose -f docker-compose.ecs.yml up -d
docker compose -f docker-compose.ecs.yml ps
```

建议将 `export` 语句写入 `/srv/venus-4s/infra/.deploy-tag.env`,发布前执行 `source .deploy-tag.env` 即可。

### 1.2 仅修改配置

**修改密钥类配置**(数据库密码、AccessKey 轮换等):

- 编辑 `/etc/venus-4s/.env`,保存文件。
- 执行 `docker compose -f /srv/venus-4s/infra/docker-compose.ecs.yml restart api cron`。
- 无需重新构建镜像。

**修改非敏感配置**(域名、限流参数、OSS Bucket 名称等):

- 编辑仓库中 `config/prod.baseline.env`。
- 重新构建镜像并按 §1.1 发布。

### 1.3 回滚

将 `API_IMAGE` 与 `WEB_IMAGE` 变量指向上一个可用 tag,重新执行 `up -d`:

```bash
export API_IMAGE=registry.cn-hangzhou.aliyuncs.com/venus/api:<上一个TAG>
export WEB_IMAGE=registry.cn-hangzhou.aliyuncs.com/venus/web:<上一个TAG>
docker compose -f docker-compose.ecs.yml up -d
```

不建议长期使用 `latest` tag 覆盖发布,否则将无法精确回滚。建议保留最近 3 至 5 个历史 tag。

若回滚涉及数据库迁移的倒退,建议优先使用 §3.3 中的"恢复到时间点"功能创建克隆实例,而非 `alembic downgrade`。

## 2. 常用运维操作

约定:后续命令假定已在 `/srv/venus-4s/infra` 目录下,并定义别名 `C="docker compose -f docker-compose.ecs.yml"`。

```bash
cd /srv/venus-4s/infra
C="docker compose -f docker-compose.ecs.yml"
```

### 2.1 常用命令

| 命令 | 说明 |
|---|---|
| `$C ps` | 查看容器状态 |
| `$C logs -f api` | 实时跟踪 api 日志 |
| `$C logs --tail=200 api` | 查看 api 最近 200 行日志 |
| `$C restart api` | 重启 api 容器 |
| `$C down` | 停止所有容器(不影响 RDS、OSS 数据) |
| `$C up -d` | 启动所有容器 |
| `$C exec api bash` | 进入 api 容器 |
| `docker image prune -a` | 清理无 tag 的镜像 |
| `docker system df` | 查看 Docker 磁盘占用 |

### 2.2 更新敏感词库

```bash
docker compose -f docker-compose.ecs.yml exec api \
    python /app/../scripts/init_sensitive_words.py add "关键词1" "关键词2"
docker compose -f docker-compose.ecs.yml restart api
```

敏感词库在 api 进程内通过 lru_cache 缓存,更新后必须重启 api 容器才能生效。

### 2.3 删除用户照片(PIPL 数据删除请求)

在数据库中标记删除:

```bash
mysql -h rm-xxxxxx.mysql.rds.aliyuncs.com -u venus -p venus \
    -e "UPDATE photos SET deleted_at=NOW() WHERE user_id=<uid>;"
```

OSS 中的对象将由 cron 定时任务在下一轮清理。如需立即删除,可使用 `ossutil` 命令行工具。

### 2.4 导出留资 CSV

```bash
cd /srv/venus-4s/infra
docker compose -f docker-compose.ecs.yml exec api \
    python /app/../scripts/export-leads.py \
    --from 2026-07-01 --to 2026-08-01 --out /tmp/leads.csv
docker cp $(docker compose -f docker-compose.ecs.yml ps -q api):/tmp/leads.csv ./
```

## 3. 数据备份与恢复(MySQL)

### 3.1 自动备份

在 RDS 实例详情页选择"备份恢复 > 备份策略"。

推荐配置:

- 数据备份保留 7 至 30 天。
- Binlog 保留 7 天,该项决定"恢复到过去时间点"的可用范围。
- 备份时间选择业务低峰时段。

默认策略已开启自动备份,可依据业务情况调整保留时长与执行窗口。

### 3.2 手动快照

在以下场景执行前,应先创建手动备份:

- 结构变更
- 批量数据操作
- 版本升级
- 迁移操作

操作方式:进入 RDS 实例的"备份恢复 > 数据备份",单击"备份实例"。备份完成通常需要数分钟至十几分钟。

### 3.3 恢复到指定时间点

推荐通过"克隆到新实例"方式恢复,验证无误后再切换 `DATABASE_URL`。

1. 进入 RDS 实例"备份恢复 > 克隆实例"。
2. 选择目标时间点与规格。
3. 等待克隆完成,获取新实例的内网地址。
4. 在克隆实例上验证数据完整性。
5. 修改 `/etc/venus-4s/.env` 中 `DATABASE_URL`,执行 `docker compose ... restart api cron` 切换。

### 3.4 Redis 备份说明

项目 Redis 中存储的数据均为可重建内容(限流计数、短信验证码、JWT 黑名单、会话缓存),丢失后仅影响当前时段的限流计数与验证码。KVStore 默认开启 AOF 持久化与主从热备,无需额外配置备份策略。

## 4. 扩容

### 4.1 MySQL 扩容

- **存储扩容**:ESSD 支持在线扩容,通过控制台操作数分钟生效。存储不支持缩容。
- **规格升配**:1 核 2 GB 升级至 2 核 4 GB 等操作会产生数秒至数分钟的连接抖动。高可用版依赖主备切换,抖动时间较短。建议在业务低峰时段操作。

### 4.2 Redis 扩容

规格变更采用热切换,抖动时间极短。

### 4.3 应用侧行为

api 与 cron 容器配置了 `restart: always`,连接中断后将自动重连。通常无需人工干预。可通过 `docker compose ... logs -f api` 观察是否出现持续报错。

### 4.4 ECS 扩容

- **系统盘扩容**:控制台在线扩容后,需在 ECS 内执行 `growpart` 与 `resize2fs` 使文件系统识别新容量。
- **规格升配**:需要重启 ECS。建议在业务低峰时段执行,提前 `docker compose ... down` 停止服务。

## 5. 数据库与 Redis 迁移

### 5.1 MySQL 迁移

1. 按 [01 §4](./01-部署前准备.md#4-创建-rds-mysql-实例) 创建新实例,配置白名单。
2. 停止应用写入:

    ```bash
    docker compose -f /srv/venus-4s/infra/docker-compose.ecs.yml stop api cron
    ```

3. 迁移数据:
    - 数据量小于 10 GB:使用 `mysqldump` 从 ECS 内网连接旧实例导出,导入新实例。
    - 数据量较大或需要不停机迁移:使用阿里云数据传输服务 DTS 的"结构迁移 + 全量迁移 + 增量迁移"模式,切换时进行短暂停写。

4. 修改 `/etc/venus-4s/.env` 中的 `DATABASE_URL`,指向新实例。
5. 重启并验证:

    ```bash
    docker compose -f /srv/venus-4s/infra/docker-compose.ecs.yml up -d
    docker compose -f /srv/venus-4s/infra/docker-compose.ecs.yml exec api curl -s localhost:8000/health
    ```

6. 建议保留旧实例至少一周,确认业务稳定后再释放。

### 5.2 Redis 迁移

Redis 中数据均可重建,采用直接切换方式即可:

1. 创建新 Redis 实例并配置白名单。
2. 修改 `REDIS_URL`,执行 `docker compose ... restart api cron`。
3. 等待旧实例中所有键 TTL 过期后释放。

无需迁移数据。

## 6. 故障排查

### 6.1 API 5xx 错误率升高

查看日志:

```bash
docker compose -f /srv/venus-4s/infra/docker-compose.ecs.yml logs --tail=500 api | grep -E '5\d\d|ERROR'
```

排查方向:

- 后端异常:定位堆栈,回滚或修复。
- 数据库连接问题:参见 §6.5。
- LLM 依赖问题:参见 §6.3。

### 6.2 微信内 H5 拦截或无法访问

- 切换至备用域名。
- 检查近期文案是否包含高敏词(如"瘦脸"、"美白"、"整容"等)。
- 联系微信广告或小程序后台申诉。
- 引导用户通过备用入口访问,如扫码或公众号菜单。

### 6.3 LLM 服务异常

查看日志:

```bash
docker compose -f /srv/venus-4s/infra/docker-compose.ecs.yml logs api | grep -E 'LLM_|RUNNER_EXCEPTION'
```

临时切换至 mock 模式维持服务可用性:

```
# 编辑 /etc/venus-4s/.env
LLM_PROVIDER=mock
```

重启容器:

```bash
docker compose -f /srv/venus-4s/infra/docker-compose.ecs.yml restart api cron
```

同时通知 LLM 服务负责人处理。

### 6.4 内容审核拒绝率异常升高

- 通常由用户上传违规内容或新词库误报导致。
- 查询 `audit_logs` 表核查具体拒绝内容。
- 应急情况下可降级为仅使用本地词库(需在代码中注释掉阿里云 textScan 调用后重新构建镜像,仅在紧急情况使用)。

### 6.5 SSE 长连接频繁断开

- 检查 nginx 配置中 `proxy_read_timeout` 是否为 3600s。
- 检查 `proxy_buffering off` 配置是否存在。
- 客户端侧:浏览器 EventSource 支持自动重连,可结合 `Last-Event-ID` 实现断点续传。
- 服务端日志:检查是否存在 `RUNNER_EXCEPTION` 或 LLM 超时错误。

### 6.6 小程序分析进度不动或连上即断(WebSocket)

小程序端的分析进度走 WebSocket(`/api/analyze/{task_id}/ws`),H5 端走 SSE。表现为进度条停在 0、
或刚进分析页连接就关闭时,按以下顺序排查:

1. **确认 nginx 有专用 location**。这是最常见的原因:

    ```bash
    docker compose -f /srv/venus-4s/infra/docker-compose.ecs.yml exec web \
      grep -A3 'analyze/.+/ws' /etc/nginx/conf.d/default.conf
    ```

    必须出现 `proxy_set_header Upgrade $http_upgrade;` 与 `proxy_set_header Connection "upgrade";`。
    缺失则请求落到通用 `location /api/`,nginx 按普通 HTTP 代理处理,握手拿不到 101。
    该 location 还必须位于通用 `location /api/` **之前**。

2. **握手返回码**。正常应为 `101`。用 nginx 访问日志确认:

    ```bash
    docker compose -f /srv/venus-4s/infra/docker-compose.ecs.yml logs --tail=100 web | grep '/ws'
    ```

    返回 200/404 说明没走到 WebSocket 分支;返回 502 说明 api 容器侧异常。

3. **跑到一半才断**,检查该 location 的 `proxy_read_timeout` / `proxy_send_timeout` 是否为 3600s。
   通用 `/api/` 只有 60s,而出一份报告可达数分钟。

4. **小程序客户端侧**:确认域名已加入微信后台的 **socket 合法域名**(与 request 合法域名是
   两份独立清单,只配了 request 会连不上),且必须是 `wss://`。

5. 服务端日志同 §6.5,检查 `RUNNER_EXCEPTION` 与 LLM 超时。

配置改动与背景说明见 [02 §8](./02-部署实施.md#8-nginx-行为说明) 与
[references/MINIAPP.md](./references/MINIAPP.md)。

### 6.7 数据库连接失败

按以下顺序排查:

1. 检查 RDS 白名单是否包含 ECS 当前内网 IP。ECS 变更 IP 后需同步更新。
2. 确认 ECS 与 RDS 位于同一地域、同一 VPC。
3. 检查 `/etc/venus-4s/.env` 中连接串:host、密码、驱动前缀、Redis 密码前的冒号是否正确。密码中的特殊字符是否已 URL 编码。
4. 查看日志:

    ```bash
    docker compose -f /srv/venus-4s/infra/docker-compose.ecs.yml logs --tail=200 api
    ```

    常见错误对照参见 [02 §11.2](./02-部署实施.md#112-api-容器-unhealthy-或反复重启)。

5. 在 ECS 上手动连接验证:

    ```bash
    mysql -h rm-xxxxxx.mysql.rds.aliyuncs.com -u venus -p venus -e 'select 1'
    redis-cli -h r-xxxxxx.redis.rds.aliyuncs.com -a '<密码>' ping
    ```

6. 查看 RDS 连接数指标:进入实例监控页面,确认连接数是否接近上限。若接近上限,分析是应用连接泄漏还是慢查询占用。

### 6.8 磁盘空间不足

```bash
df -h
docker system df
docker image prune -a
docker volume prune
journalctl --vacuum-size=200M
```

RDS 磁盘空间不足时,可在控制台执行在线扩容,数分钟生效。

## 7. 性能观察

### 7.1 MySQL 慢查询

在 RDS 实例的"CloudDBA > SQL 洞察"或"慢 SQL"页面查看慢查询记录。建议上线后一周内每日检查,重点关注执行时间超过 1 秒的语句。

### 7.2 资源监控

RDS 实例的"监控与报警"页面提供 CPU、连接数、IOPS 等指标。建议为生产实例配置以下告警:

- CPU 使用率超过 80% 且持续 5 分钟
- 连接数超过阈值的 80%
- 磁盘剩余空间低于 20%

告警通知可对接飞书、钉钉等渠道。

### 7.3 Redis 性能

KVStore 控制台的"性能监控"页面提供内存使用率、命中率、大 key 分析等指标。项目负载较低时重点关注内存使用率,避免触发淘汰策略。

### 7.4 应用侧关键指标

| 指标 | 阈值 | 处置措施 |
|---|---|---|
| API 5xx 比例 | 每分钟超过 1% | 立即排查,参见 §6.1 |
| LLM 超时 | 5 分钟内超过 10 次 | 联系 LLM 服务负责人,必要时切换至 mock,参见 §6.3 |
| 内容审核拒绝 | 每小时超过 30 次 | 排查是否遭遇攻击或词库误报,参见 §6.4 |
| RDS 磁盘使用率 | 超过 80% | 在线扩容 |
| ECS 磁盘使用率 | 超过 80% | 清理 Docker 镜像与系统日志,参见 §6.7 |
| 备份失败 | 连续 2 天 | 立即排查 |

## 8. 安全事件响应

发生安全事件时,按以下顺序处置:

1. **立即停止服务**:

    ```bash
    docker compose -f /srv/venus-4s/infra/docker-compose.ecs.yml down
    ```

2. **保留取证数据**:

    ```bash
    mysqldump --single-transaction -h rm-xxxxxx.mysql.rds.aliyuncs.com \
        -u venus -p venus > /var/venus-backups/incident-$(date -u +%Y%m%dT%H%M%SZ).sql
    ```

3. 通知项目安全或法务负责人。
4. 修复问题后重新启动服务。

**AccessKey 疑似泄露**:在 RAM 控制台删除旧 AccessKey,创建新 AccessKey,修改 `/etc/venus-4s/.env` 中相关配置,重启容器。旧 AccessKey 删除后立即失效。

**数据库密码疑似泄露**:在 RDS 控制台的"账号管理"中重置账号密码,修改 `/etc/venus-4s/.env` 中 `DATABASE_URL`,重启容器。

## 9. 定期维护计划

### 每周

- 查看 RDS 与 Redis 监控指标:CPU、连接数、磁盘、内存。
- 查看 api 容器最近 7 天日志,确认无反复出现的错误。
- 确认 RDS 自动备份每日成功执行。

### 每月

- 检查 SSL 证书剩余有效期。
- 清理 Docker 磁盘占用:`docker image prune -a`。
- 归档或清理应用日志。

### 每季度

- 演练回滚流程:将镜像 tag 切换至上一版本,验证服务正常后切回当前版本。
- 演练数据库恢复流程:通过"克隆实例"功能恢复到指定时间点,连接验证数据一致性(不影响生产实例)。
- 复审 RAM 权限,将 FullAccess 策略收敛为最小必要权限。

### 每年

- 域名续费。
- SSL 证书续期。免费 DV 证书通常每年续期,Let's Encrypt 每 90 天续期,建议提前 30 天操作。
- 阿里云资源续费。
