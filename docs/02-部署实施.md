# 02 · 部署实施

## 适用读者与目标

本文档面向已完成 [01-部署前准备.md](./01-部署前准备.md) §15 检查的技术人员。

本阶段目标:

- 在本地构建 api 与 web 镜像,并推送至阿里云 ACR。
- 在 ECS 上安装 Docker、部署镜像、初始化数据库、启动全部容器。
- 完成容器内部的基本连通性验证。

预计操作耗时 1 至 2 小时(镜像构建约 10 至 20 分钟)。

## 0. 操作分工

- **本地操作**:填写构建配置、构建镜像、推送镜像。需要在本地机器安装 Docker Desktop。
- **ECS 操作**:通过 SSH 登录后安装 Docker、拉取镜像、配置密钥、启动容器。

若本地机器无法安装 Docker,可将构建过程也在 ECS 上完成,流程不变。

## 1. 获取项目代码

在本地任意目录执行:

```bash
git clone <项目仓库地址> venus-4s
cd venus-4s
```

## 2. 配置构建参数

### 2.1 编辑 `infra/build.conf`

`infra/build.conf` 用于指定构建后镜像的推送位置。执行:

```bash
cp infra/build.conf.example infra/build.conf
```

编辑 `infra/build.conf`,依据 [01 §15](./01-部署前准备.md#15-信息汇总表) 表 A 中的 ACR 信息填写:

```
ACR_REGISTRY=registry.cn-hangzhou.aliyuncs.com
ACR_NAMESPACE=venus
IMAGE_TAG=v1.0.0
PLATFORM=linux/amd64
```

配置项说明:

| 配置项 | 说明 |
|---|---|
| `ACR_REGISTRY` | ACR 公网地址,填写实际所在地域的地址 |
| `ACR_NAMESPACE` | ACR 命名空间名称 |
| `IMAGE_TAG` | 镜像标签。建议使用版本号或日期,避免长期使用 `latest`,以支持回滚 |
| `PLATFORM` | 目标架构。ECS 通常为 x86_64,填写 `linux/amd64` |

**注意**:在 Apple Silicon 平台上为 x86 ECS 构建时,必须显式指定 `PLATFORM=linux/amd64`,否则将生成 arm64 镜像,在 ECS 上无法运行。

### 2.2 编辑 `config/prod.baseline.env`

`config/prod.baseline.env` 是构建时打包进 api 镜像的非敏感配置文件,需将其中的占位符替换为实际值。

需要修改的配置项:

| 配置项 | 修改为 |
|---|---|
| `APP_BASE_URL` | `https://<你的域名>` |
| `WEB_BASE_URL` | `https://<你的域名>` |
| `ALI_REGION` | 与 ECS 所在地域一致,例如 `cn-hangzhou` |
| `OSS_BUCKET` | 汇总表中的 Bucket 名称 |
| `OSS_ENDPOINT` | 汇总表中的外网 Endpoint |
| `OSS_INTERNAL_ENDPOINT` | 汇总表中的内网 Endpoint |
| `OSS_STS_ROLE_ARN` | `acs:ram::<主账号ID>:role/venus-uploader` |
| `ALI_GREEN_REGION` | `cn-shanghai`(内容审核推荐区域) |
| `ALI_SMS_SIGN` | 已审核通过的短信签名 |
| `ALI_SMS_TEMPLATE_LOGIN` | 已审核通过的短信模板 Code |
| `LLM_PROVIDER` | 依据 LLM 对接方式选择 `qwen` 或 `qwen-sync` |
| `LLM_SYNC_BASE_URL` 或 `LLM_QWEN_BASE_URL` | LLM 服务方提供的接口地址 |

保持默认值即可的配置项:`APP_ENV=prod`、`APP_DEBUG=false`、限流参数、照片 TTL 等。

`CORS_ORIGINS` **保持留空**:本部署方案中前端与 API 同域(nginx 反代 `/api`),本就没有跨域,
留空即不挂 CORS 中间件。仅当把 H5 单独挂到另一个域名(例如走 CDN)时才填该域名的完整 origin,
多个用逗号分隔。微信小程序不受浏览器同源策略约束,与此项无关——它看的是微信后台的
「服务器域名」白名单。详见 [config/README.md](../config/README.md)。

**严禁**在此文件中写入以下密钥类配置:`DATABASE_URL`、`REDIS_URL`、`JWT_SECRET`、`PHONE_DEK_BASE64`、`PHONE_HMAC_KEY`、`ALI_ACCESS_KEY_ID`、`ALI_ACCESS_KEY_SECRET`。这些配置必须写入服务器 `/etc/venus-4s/.env`(详见 §6)。构建脚本 `infra/build.sh` 会扫描此文件,发现上述密钥项将终止构建并报错。

## 3. 构建并推送镜像

### 3.1 登录 ACR

首次操作需登录 ACR。执行:

```bash
docker login registry.cn-hangzhou.aliyuncs.com
```

输入 [01 §15](./01-部署前准备.md#15-信息汇总表) 表 A 中记录的 ACR 用户名和密码。返回 `Login Succeeded` 表示登录成功。登录凭证保存于本地 `~/.docker/config.json`,后续操作无需重复登录。

### 3.2 执行构建

在项目根目录执行:

```bash
bash infra/build.sh --push
```

脚本执行流程:

1. 校验配置文件、锁文件、Dockerfile 是否齐全,并确认 `config/prod.baseline.env` 不含密钥。
2. 使用 `apps/api/Dockerfile` 构建 api 镜像。
3. 使用 `apps/web/Dockerfile` 构建 web 镜像。
4. 登录 ACR,推送两个镜像。

首次构建约需 10 至 20 分钟(需下载依赖),后续构建可利用 Docker 层缓存显著缩短耗时。

其他常用参数:

```bash
bash infra/build.sh                          # 仅本地构建,不推送
bash infra/build.sh --tag=v1.2.0 --push      # 指定 tag 并推送
bash infra/build.sh --platform=linux/amd64 --push
```

### 3.3 确认镜像已推送

在 ACR 控制台进入命名空间 `venus` 下的 `api` 与 `web` 仓库,在"镜像版本"页应能看到刚推送的 tag。

也可在本地执行:

```bash
docker manifest inspect registry.cn-hangzhou.aliyuncs.com/venus/api:v1.0.0
```

命令返回镜像元数据表示推送成功。

构建脚本执行完成后,终端会输出后续部署所需的 `export API_IMAGE=...` 与 `export WEB_IMAGE=...` 语句,请记录备用。

## 4. 在 ECS 上安装 Docker

通过 SSH 登录 ECS:

```bash
ssh root@<ECS 公网 IP>
```

### 4.1 安装 Docker

CentOS 或 Alibaba Cloud Linux:

```bash
sudo yum install -y docker
sudo systemctl enable --now docker
```

Ubuntu 22.04:

```bash
sudo apt-get update
sudo apt-get install -y docker.io
sudo systemctl enable --now docker
```

### 4.2 安装 Docker Compose 插件

```bash
sudo mkdir -p /usr/local/lib/docker/cli-plugins
sudo curl -SL https://github.com/docker/compose/releases/latest/download/docker-compose-linux-x86_64 \
    -o /usr/local/lib/docker/cli-plugins/docker-compose
sudo chmod +x /usr/local/lib/docker/cli-plugins/docker-compose
docker compose version
```

命令返回版本号即安装成功。

### 4.3 登录 ACR

```bash
docker login registry.cn-hangzhou.aliyuncs.com
```

用户名、密码同 §3.1。

如需通过 VPC 内网拉取镜像以节省流量,可改用 VPC 地址:

```bash
docker login registry-vpc.cn-hangzhou.aliyuncs.com
```

## 5. 上传 infra 目录至 ECS

在本地项目根目录执行:

```bash
scp -r infra/ root@<ECS 公网 IP>:/srv/venus-4s/
```

上传后 ECS 上应存在以下内容:

- `/srv/venus-4s/infra/docker-compose.ecs.yml`:定义 web、api、cron 三个容器,不包含 MySQL 与 Redis(使用托管服务)。
- `/srv/venus-4s/infra/nginx/edge.conf`:nginx 配置文件。
- `/srv/venus-4s/infra/nginx/ssl/`:SSL 证书目录(§7 中放入证书文件)。
- `/srv/venus-4s/config/prod.baseline.env`:该文件在此路径不会被容器读取,可忽略。

## 6. 在 ECS 上配置密钥文件

密钥类配置写入 `/etc/venus-4s/.env`,该文件通过 `docker-compose.ecs.yml` 的 `env_file` 指令在容器启动时注入。

执行:

```bash
sudo mkdir -p /etc/venus-4s
sudo cp /srv/venus-4s/config/prod.secrets.example /etc/venus-4s/.env
sudo vim /etc/venus-4s/.env
sudo chmod 600 /etc/venus-4s/.env
```

依据 [01 §15](./01-部署前准备.md#15-信息汇总表) 表 A 与表 B 填写以下配置项:

```
APP_ENV=prod
APP_BASE_URL=https://<你的域名>
WEB_BASE_URL=https://<你的域名>

DATABASE_URL=mysql+aiomysql://venus:<RDS密码>@rm-xxxxxx.mysql.rds.aliyuncs.com:3306/venus?charset=utf8mb4
REDIS_URL=redis://:<Redis密码>@r-xxxxxx.redis.rds.aliyuncs.com:6379/0

JWT_SECRET=<本地生成值>
PHONE_DEK_BASE64=<本地生成值>
PHONE_HMAC_KEY=<本地生成值>

ALI_ACCESS_KEY_ID=<AccessKey ID>
ALI_ACCESS_KEY_SECRET=<AccessKey Secret>
```

**常见错误**:

- 数据库驱动前缀必须为 `mysql+aiomysql://`,不是 `mysql://`。
- Redis 连接串中密码前的冒号不可省略,格式为 `redis://:密码@host:6379/0`。
- 若密码包含 `@`、`:`、`/`、`?`、`#` 等特殊字符,需进行 URL 编码(例如 `@` 编码为 `%40`)。

## 7. 部署 SSL 证书

将 [01 §11.4](./01-部署前准备.md#114-申请-ssl-证书) 中准备的证书文件上传至 ECS。

在本地执行:

```bash
scp fullchain.pem privkey.pem root@<ECS 公网 IP>:/srv/venus-4s/infra/nginx/ssl/
```

在 ECS 上设置文件权限:

```bash
sudo chmod 600 /srv/venus-4s/infra/nginx/ssl/*.pem
ls -l /srv/venus-4s/infra/nginx/ssl/
```

**文件命名必须为 `fullchain.pem` 与 `privkey.pem`**,这是 `edge.conf` 中引用的固定路径:

```nginx
ssl_certificate     /etc/nginx/ssl/fullchain.pem;
ssl_certificate_key /etc/nginx/ssl/privkey.pem;
```

## 8. nginx 行为说明

ECS 无需单独安装 nginx。web 容器镜像内已包含 nginx,`docker-compose.ecs.yml` 通过 Volume 将 `infra/nginx/edge.conf` 挂载至容器的 `/etc/nginx/conf.d/default.conf`:

```yaml
web:
  image: ${WEB_IMAGE:?}
  ports:
    - "80:80"
    - "443:443"
  volumes:
    - ./nginx/edge.conf:/etc/nginx/conf.d/default.conf:ro
    - ./nginx/ssl:/etc/nginx/ssl:ro
```

容器启动后,nginx 提供以下功能:

- 80 端口:除 `/.well-known/acme-challenge/`(用于 ACME 证书校验)外,其他请求 301 跳转至 HTTPS。
- 443 端口:TLS 终止,读取 `nginx/ssl/fullchain.pem` 与 `privkey.pem`。
- `/api/` 路径:反向代理至 api 容器 8000 端口,读取超时 60 秒。
- `/api/analyze/*/stream` 路径:SSE 长连接配置,关闭 buffering 与 cache,读取超时 3600 秒。
- `/api/analyze/*/ws` 路径:WebSocket 长连接配置,转发 `Upgrade`/`Connection` 头完成协议升级,关闭 buffering,读写超时 3600 秒。
- 其他路径:静态资源托管,SPA 场景 fallback 至 `index.html`。

> **`/api/analyze/*/ws` 这条不可省略。** 小程序端的分析进度走 WebSocket(H5 端走 SSE)。
> 若删掉该 location、让请求落到通用 `/api/`,由于后者未转发 `Upgrade`/`Connection` 头,
> nginx 会按普通 HTTP 代理处理,握手拿不到 101,客户端表现为「连上即断、进度不动」;
> 且通用 `/api/` 的读取超时仅 60 秒,而出一份报告可达数分钟,连接会被中途掐断。
> 该 location 必须写在通用 `location /api/` 之前。

如需修改 nginx 配置(例如增加域名或路径规则),编辑仓库中的 `infra/nginx/edge.conf`,通过 `scp` 覆盖 ECS 上的对应文件,再执行 `docker compose -f docker-compose.ecs.yml restart web` 生效。此过程无需重新构建镜像。

修改后建议先验证语法,避免 restart 后 nginx 起不来:

```bash
docker compose -f docker-compose.ecs.yml exec web nginx -t
```

> `infra/nginx/web.conf` 是烤进 web 镜像的内层静态服务配置,不涉及 `/api` 反代。
> 也就是说 `/api` 反代规则只有 `edge.conf` 这一处,改它就够了。

## 9. 初始化数据库并启动容器

在 ECS 上执行:

```bash
cd /srv/venus-4s/infra

export API_IMAGE=registry.cn-hangzhou.aliyuncs.com/venus/api:v1.0.0
export WEB_IMAGE=registry.cn-hangzhou.aliyuncs.com/venus/web:v1.0.0

docker compose -f docker-compose.ecs.yml pull
docker compose -f docker-compose.ecs.yml run --rm api alembic upgrade head
docker compose -f docker-compose.ecs.yml up -d
docker compose -f docker-compose.ecs.yml ps
```

命令说明:

| 命令 | 说明 |
|---|---|
| `docker compose ... pull` | 从 ACR 拉取镜像 |
| `docker compose ... run --rm api alembic upgrade head` | 首次部署时执行数据库迁移,创建表结构。后续每次发布若包含新迁移,均需重新执行 |
| `docker compose ... up -d` | 后台启动全部容器 |
| `docker compose ... ps` | 查看容器状态 |

预期输出:

```
NAME                    STATUS
infra-api-1             Up (healthy)
infra-cron-1            Up
infra-web-1             Up
```

若 api 容器未进入 healthy 状态,执行 `docker compose -f docker-compose.ecs.yml logs api` 查看日志。常见错误参见 §11。

建议将 `export` 语句写入 `/srv/venus-4s/infra/.deploy-tag.env`,后续操作前执行 `source .deploy-tag.env` 即可。

## 10. 容器内部验证

### 10.1 api 容器健康检查

```bash
docker compose -f /srv/venus-4s/infra/docker-compose.ecs.yml \
    exec api curl -s localhost:8000/health
```

预期返回:

```json
{"status":"ok"}
```

### 10.2 通过 nginx 访问

若 DNS 解析已生效:

```bash
curl -k https://<你的域名>/health
```

若 DNS 尚未生效,可指定解析:

```bash
curl -k --resolve <你的域名>:443:127.0.0.1 https://<你的域名>/health
```

### 10.3 执行冒烟测试

项目仓库中 `scripts/smoke.sh` 提供 5 项基本检查:健康检查、OpenAPI 可达性、短信限流、验证码错误响应、静态首页可达性。

执行:

```bash
HOST=https://<你的域名> bash scripts/smoke.sh
```

预期输出:

```
smoke OK
```

## 11. 故障排查

### 11.1 镜像拉取失败

- 确认 `docker login` 已成功执行。
- 通过 ACR 控制台确认目标 tag 已存在。
- 确认 ECS 具备访问 ACR 的网络路径。公网地址走公网,`registry-vpc.*` 走 VPC 内网。

### 11.2 api 容器 unhealthy 或反复重启

查看日志:

```bash
docker compose -f /srv/venus-4s/infra/docker-compose.ecs.yml logs --tail=200 api
```

常见错误对照表:

| 报错信息 | 可能原因 |
|---|---|
| `Access denied for user` | `DATABASE_URL` 密码错误或未进行 URL 编码 |
| `Can't connect to MySQL server` | RDS 白名单未加入 ECS 内网 IP;RDS 与 ECS 不在同一 VPC;host 拼写错误 |
| `NOAUTH Authentication required` 或 `WRONGPASS` | `REDIS_URL` 密码错误或密码前冒号缺失 |
| `ModuleNotFoundError: aiomysql` | 数据库驱动前缀缺失 `+aiomysql` |
| 缺少环境变量类错误 | `/etc/venus-4s/.env` 未正确填写或权限设置错误 |

### 11.3 web 容器可访问但 HTTPS 报错

- 确认 `nginx/ssl/` 下证书文件命名为 `fullchain.pem` 与 `privkey.pem`。
- 确认文件权限为 600 且容器可读。

### 11.4 在 ECS 上手动验证 RDS 与 Redis 连通性

安装客户端工具:

```bash
yum install -y mysql redis
```

测试连接:

```bash
mysql -h rm-xxxxxx.mysql.rds.aliyuncs.com -u venus -p venus -e 'select 1'
redis-cli -h r-xxxxxx.redis.rds.aliyuncs.com -a '<密码>' ping
```

Redis 应返回 `PONG`。若手动连接失败,应用连接必定失败,可优先排查白名单与 VPC 配置。
